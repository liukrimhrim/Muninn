# Adversarial review of the module design

Status: review of [module-design.md](module-design.md) as of 2026-10-15, checked against the compatibility, lifecycle and data contracts, the closure records and ticket 20. Findings are design defects in the written contracts, not measured implementation failures.

## What holds

- All 27 current domain record kinds have one owner: 17 from the [compatibility record table](compatibility-design.md#3-portable-logical-records), six from the [observability data contract](../learning-observability/data-contract.md), plus `teaching`, `practice_offer`, `condition_checkpoint` and `concern`.
- Every cited anchor resolves. The declared allowed-import graph is acyclic as stated.
- No model request inside a write transaction, FSRS adapter private to Practice and the budget-as-input rule are consistent with the lifecycle and compatibility contracts.

## Findings

Ranked by how much downstream work inherits the defect. The first three move seams; fix them before anything builds on this design.

| # | Finding | Evidence | Proposed fix |
|---|---|---|---|
| A01 | **`transition` violates "owner controls meaning".** Application Workflows owns the record but "does not decide correctness or eligibility". `transition.check_effects` carries `preserved/reanchored/no_advance/pending/held`, `revokes_reservation` and `resolution_rule`: Practice scheduling decisions the coordinator cannot validate. | [Correction after later checks](learning-lifecycle-contract.md#correction-after-later-checks); module design "One owner per rule and record" | Practice owns scheduling effects, as its own record or as fields of the schedule revision. `transition` shrinks to a coordination receipt: scope, category, actor, before/after refs. |
| A02 | **Owner/extra is stored twice under two owners.** `attempt.purpose: due/extra` is Evidence-owned; `practice_offer.slots[].role: owner/extra` is Practice-owned. A stale submission is "classified extra for any slot it never owned", a Practice decision that must land in an Evidence record or the two fields disagree. | [compatibility `attempt`](compatibility-design.md#3-portable-logical-records); [lifecycle §4](learning-lifecycle-contract.md#4-one-due-opportunity-two-tabs-and-late-grading) | Remove `due/extra` from `attempt.purpose`. Owner/extra is derived from the offer slot only. |
| A03 | **The claim contract has no owner.** `Evidence.qualify` accepts a caller-built claim contract. Practice builds one for scheduling; Measurement builds one for reports. M04 requires "the same claim contract", but the design has two constructors, which is the duplicated interpretation rule the design forbids. | Module design "Shared rule" table, M04 | Publish named claim contracts as `Algorithm` identities from one owner. Measurement references them by identity and labels any variant as a distinct claim. |
| A04 | **Time and duration semantics are split three ways.** The design says Evidence owns learning-time claims and Measurement owns measured duration. `session` (Practice) carries `started_at/ended_at` with time evidence and `elapsed_ms`; `attempt.elapsed_ms` is Evidence-owned. "Nested values follow their containing record" makes Practice the owner of session timing. Session is also Measurement's cost-scope fallback. The locality claim "duration rules change only Measurement" is false. | [compatibility `session`, `attempt`](compatibility-design.md#3-portable-logical-records); [data contract §3–4](../learning-observability/data-contract.md#3-occurrence-time-is-evidence-not-a-required-guess) | Remove `elapsed_ms` from `attempt` and `session` (`activity_span` is the duration record) or declare them derived caches. Name which module validates session time evidence. |
| A05 | **Encapsulation is nominal.** "Records remain private except their portable representation", yet the compatibility contract specifies every field of every record as the portable format and import performs cross-record semantic validation. The private shape is the public shape. The only genuinely private state is FSRS `engine_state`. | [compatibility record table](compatibility-design.md#3-portable-logical-records); [import validation](compatibility-design.md#4-snapshot-and-export-format) | State that records are public data with single-writer ownership. Reserve "private" for engine state and repository code. |
| A06 | **Enforcement is unspecified.** "Enforce the owner map and allowed imports rather than naming conventions": in one process over one SQLite file any repository can write any table. Runtime enforcement needs Library to know kind-to-owner (contradicting "Library: no domain module") and a caller identity on the transaction context. Neither is specified. | Module design "Shared transaction, private responsibilities", M01 | Declare the honest mechanism: an import-lint rule for the allowed graph and one test that scans each module's SQL for foreign tables. Do not promise runtime guards. |
| A07 | **Library migration and export contradict private tables.** "Change physical storage layout: Library and affected owners' private repositories/migrations." If tables are private, Library cannot migrate or export them. If Library does, they are not private. Owner-registered serializers are the plugin registry the design disclaims. | Module design Library row and "Changes that should stay local" | Library owns envelope, sequence, receipts and the transaction. Application Workflows drives export and validation by calling each owner's export and validate operations through fixed wiring. |
| A08 | **Practice–Measurement cycle prevention is half-done.** The budget is passed through Application Workflows to avoid an import, but Measurement still imports Practice for "offer facts" and historical state. The same device (pass practice views as input) removes the edge. M07 says Measurement "cannot increase exercise demand"; it can reduce it, because unknown or disputed duration in the budget summary shrinks the effective budget and changes selection. | Module design "Prevent two likely dependency cycles", M07 | Either drop Measurement→Practice and pass views, or state plainly that Measurement affects selection through the budget and test that effect. |
| A09 | **"Low coupling" is not shown.** The graph is a chain Measurement→Practice→Evidence→Content; Measurement imports three domain modules plus Library. This is strict layering. | Module design dependency table | Describe it as layering. Keep the acyclicity claim; drop the low-coupling claim until M10 produces evidence. |
| A10 | **Hold versus failed participant.** The module design says a failed participant rolls back the whole command. The lifecycle and compatibility contracts say an unavailable engine or unresolved order produces a hold. If Practice returning a hold during correction reconciliation counts as failure, an accepted assessment correction is lost because the FSRS adapter is unavailable. | [lifecycle recall replay](learning-lifecycle-contract.md#correction-after-later-checks); [compatibility C14](compatibility-design.md#9-concrete-acceptance-cases) | Define hold as a successful participant outcome recorded in the schedule; only an invariant violation rolls back. |
| A11 | **Submit seam.** "First save the actual response and submitted-offer state in a short command" and "save a credential-free pending operation before requesting the model": one command or two? A crash between them leaves a submitted attempt with no operation, which "continue saved external operations" cannot find. | Module design "Save and assess an answer" | One command, or a specified sweep for submitted attempts lacking an operation. |
| A12 | **M03 tests SQLite, not the design.** Injecting failure between two writes in one transaction checks a database guarantee. The real atomicity risk is outside the transaction: pending operation, model call, acceptance command. | Module design M03 | Reframe M03 around the two-command seam: answer saved, operation pending, process dies, resume. |
| A13 | **M05 is trivially green.** Single-writer SQLite serializes "concurrent starts". The real hazard is two tabs with stale expected revisions taking the conflict path that must return the existing draft. | Module design M05; [lifecycle §4](learning-lifecycle-contract.md#4-one-due-opportunity-two-tabs-and-late-grading) | Test the stale-revision conflict path, not the serialized write. |
| A14 | **Provider adapter placement.** "Change model provider: owned Content/Evidence adapter/configuration" implies two adapters or a hidden eighth module. | Module design "Interface conditions and degradation" | One adapter under Application Workflows, which already owns authorized invocation. Content and Evidence own packets and response validation only. |
| A15 | **`operation` shows the A01 pattern, milder.** `purpose: draft_material/assess_answer`, `outputs` and acceptance disposition are Content/Evidence semantics inside an Application Workflows record. | [compatibility `operation`](compatibility-design.md#3-portable-logical-records) | Acceptable if `operation` is defined as lifecycle only and acceptance disposition is written by the owning module through the coordinator. Say so. |
| A16 | **"Checkpoint" is overloaded.** Enrollment checkpoints are Practice awards; `condition_checkpoint` is Evidence's prospective boundary. | Module design ownership table | Rename one; `condition_boundary` is available. |
| A17 | **Seven modules for slice 1 is heavy.** Web Interaction as a peer module with dependency arrows is the UI layer. The honest minimum for the first persisted encounter is four domain packages, an application layer and a store. | Module design "Verification and build placement"; [first-build plan](first-build-plan.md#build-order-and-exit-checks) | Keep the seven responsibilities as vocabulary; build four packages plus application and store, and let M10 decide whether Library or Web earn separate packages. |
| A18 | **Baseline provenance.** The cited baseline `0127a4f` is not an ancestor of the checked-out head `2db1c4d` on `codex/prototype/next-session-plan`; it lives on `codex/research/observability-campaign` in another worktree. `module-design.md` is untracked in this checkout. Copies are identical today and will drift. | `git merge-base --is-ancestor`, `git worktree list` | Commit the design documents on one branch and cite that branch as the baseline. |

## Verification and limits

Checked: anchor resolution for every link in the module design; record-kind coverage by counting kinds across the compatibility, observability and lifecycle contracts; acyclicity of the declared import table; and the cross-document field reads cited above. Not checked: any running code, actual atomicity, or that the proposed fixes are the only acceptable ones. A01–A03 are the findings that change record contracts; the rest are wording, placement or verification corrections.
